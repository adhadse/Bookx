# Translation review (agent review, 2026-11-21)

Scope: `po/de.po` and `po/es.po` (complete, 3339 strings), `po/fr.po` (254) and `po/hi.po` (177) as they were at
`main` 5b05e40 plus the working tree of that day. Method: 80 random entries per language read for meaning
(seed 7: de, es, fr, hi), plus mechanical checks over **every** entry of the four files: placeholder count and
order, plural forms, markup (`<…>`, backticks), line breaks, access underscores, leading/trailing space, final
punctuation and ellipsis, first-letter case, empty or copied text, and term counts for the glossary
(`po/GLOSSARY.md`). Nothing here has been applied: the po files are being regenerated by other work, so the lead
applies the fixes below afterwards (and re-checks that each `msgid` still exists).

**Verdict.** The text is good: in 160 sampled de/es entries there is no wrong meaning, no broken sentence and no
literal machine-translation nonsense. Placeholders, plural forms and markup match in all 3339 entries of both files.
The problems are consistency problems, listed below. The files stay `machine-translated` in `po/STATUS.md` (a
native read is still needed; this review does not change that).

## Top error patterns (for the next agent translating)

1. **Address form drift** (de du/Sie, es tú/usted): the main reason for a native-speaker review. Fix by always
   reading the glossary header before translating, and grep for the other form afterwards.
2. **Punctuation copied or invented**: ellipsis added or spaced differently from the source, a dropped `…`.
3. **Term drift** for words that have two English-looking synonyms (cover / title image, stylesheet plural, rating / note).
4. **Whitespace**: leading/trailing spaces of the msgid not reproduced exactly.
5. **English capitalisation rules carried into languages that do not use them**: not found in de/es (good).
